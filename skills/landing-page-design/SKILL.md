# 冈部伦太郎专属版补丁（本节优先于下方原规则中冲突处，用户当面要求除外）

来源：基于 elayadesign/ai-design-skills 的 landing-page-design 改编，MIT 协议，原作者版权与文末原 Credits 段保留，不删除。下方视觉系统（字体、间距、圆角、动效）全部保留，只改以下几点：

1. 默认中文：文案、标题、FAQ、按钮默认出中文，除非用户要求英文。
2. 不编造：人物、证言、数字、收入、经历、功效一律以用户给的真实材料为准，没有材料就留空位标注待填，不编成就、不编案例。
3. 电脑优先：落地页的买家大部分用电脑浏览，默认按桌面端设计。首屏、结构、CTA、排版先保证电脑端完整好用；移动端只要求不错乱、不遮挡。
4. 免费路线优先：部署和第三方服务优先免费、无需绑卡的方案；出现收费或绑卡提示先停下告诉用户，不擅自开通。
5. 个人品牌署名：只在为用户个人品牌做页面时，署名严格用「冈部伦太郎」，不另起账号名。

# 落地页设计

落地页不是首页。首页服务多种意图。落地页只赢一个意图：

**一个卖点 → 一个受众 → 一个核心行动。**

本技能分两部分。**Part A** 决定页面说什么、怎么组织。**Part B** 是不可协商的视觉系统。先走完 A，再碰 B。

## 适用范围

适用于所有网页界面工作：落地页、营销站、组件、仪表盘、原型和设计评审。当这里的规则与框架默认值冲突时，以本文件为准。当用户的明确要求与规则冲突时，以用户为准。

**配套技能。** 如果是升级*已有*网站而不是从零新建，请使用 `redesign-existing-projects`（[github.com/elayadesign/redesign-skill](https://github.com/elayadesign/redesign-skill)）。它负责诊断通用问题，具体数值一律以本文件为准。

# PART A — 策略与结构

## A1. 需求收集

在设计或写文案之前，先收集以下信息。只问缺失的部分，并且一次性批量提问，不要一个问题一个问题地问。

**目的**
- 唯一的核心行动是什么？（试用、演示、购买、候补名单、下载）
- 卖点到底是什么，用户具体能得到什么？
- 什么算一次转化？（点击、注册、购买）

**受众与背景**
- 理想客户画像（ICP）是谁？
- 他们想解决什么问题？
- 最主要的三个异议是什么，也就是他们今天为什么不转化
- 流量来源：广告、搜索、社交、邮件
- 访客来到页面时，已经了解了什么？

**证明与素材**
- 证明点：Logo、客户证言、数字、案例研究
- 截图、演示视频、产品动图
- 保障、退款条款、取消条款

**限制条件**
- 品牌语气：随意还是专业
- 设计方向：极简编辑风、趣味 3D、玻璃拟态
- 桌面端优先？

如果用户答不上来，就做一个合理的假设，用一句话说明，然后继续。不要因此停下整个搭建。

## A2. 页面结构

**首屏（必需）**
1. 标题：结果加受众
2. 副标题：说明怎么做，并增加具体性
3. 核心 CTA：清晰的动词加用户能得到的东西
4. 一个证明信号：Logo 墙、数据或简短证言
5. 首屏视觉：产品截图、视频或一张有力的插图

**页面中部（论证部分）**
6. 从问题到解决方案，一个区块
7. 收益，三到五条，以结果为导向
8. 使用方法，三个步骤
9. 社会证明，客户证言或案例研究

**页面底部（处理异议）**
10. FAQ，六到十二个问题
11. 风险逆转：试用、随时取消、保障
12. 结尾 CTA，与顶部完全一致

在页面中部的论证部分安排 B11 规定的强制性标语揭示区块，通常放在首屏之后或收益之后。

## A3. 版式选择

选一种，并说明为什么选它。

| 类型 | 适用场景 |
|---|---|
| **A. 经典首屏加区块** | 从首屏截图就能看懂产品。最常见。 |
| **B. 长篇故事** | 需要先教育用户、消除怀疑。 |
| **C. 极简转化页** | 高意向流量（邮件发给已知用户），或下载、候补名单这类简短卖点。 |
| **D. 对比页** | 搜索意图包含竞品（“X 对比 Y”“最好用的”）。通常搭配 SEO 页面。 |

## A4. 转化规则

**信息与来源匹配。** 如果流量来自广告，首屏标题要呼应广告标题，保持同样的承诺和视觉基调。

**让下一步显而易见。** 只有一个核心 CTA。首屏上方绝不要放相互竞争的 CTA。

**先写收益。** 功能是它能做什么。收益是这对用户意味着什么。

**要具体。**
- ❌ “节省时间、提升效率”
- ✅ “把每周报表时间从 4 小时砍到 15 分钟”

**降低风险。** 至少选一种：免费试用、免费版、无需信用卡、随时取消、退款保障。

**把异议当作一个区块，而不是脚注。** 对于高摩擦的卖点，把 FAQ 往前移。把证明直接放在它所支撑的主张旁边。

## A5. 文案

**标题公式**
- “{结果}，无需 {痛点}”
- “面向 {受众} 的 {品类}”
- “在 {时间} 内交付 {结果}”

**副标题。** 一到两句话。讲清楚这是什么、面向谁。

**CTA。** 动词加用户能得到的东西。不要用“了解更多”或“提交”。要用“开始免费试用”“预约演示”“获取清单”。

**收益要点。** 加粗收益，再接证明或细节。例如：**更快迭代** —— 一键生成三种版式变体。

注意：B1 的文案规则仍然适用。正文中不得使用连字符，不得出现孤字。

## A6. 搭建顺序

按以下顺序，一个区块一个区块地做：

1. 首屏
2. 收益
3. 使用方法
4. 证明
5. FAQ
6. 结尾 CTA

每次迭代都不要重建整个页面。按区块推进，才能控制范围，改动也便于评审。

## A7. SEO 与 AEO

**不要收录**纯广告活动页或时效性很强的卖点。用 `noindex`，或把它们放在不收录的路径下。

**应当收录**常青卖点，以及搜索意图与承诺匹配的页面。加上清晰的标题和 meta 描述、来自首页和功能页的内链，以及面向 AEO 的、简明问答形式的 FAQ。如果合适，再加 FAQ 结构化数据。

## A8. 常见坑

- 首屏上方 CTA 太多
- 价值主张含糊：“提升效率”“优化”
- 一大串功能列表，却没有结果
- 证明被埋在页面底部
- 移动端布局破坏可读性
- 没有明确的下一步

# PART B — 视觉系统

所有视觉数值都必须通过以下规则确定，不得临时凭感觉编造。

## B1. 字体排版

### 字体

**使用：** Geist、Manrope、Geist Mono、Poppins。

**禁止使用：** Inter、Roboto、Arial、Open Sans、Helvetica。

**界面中任何地方都禁止使用斜体。**

**一个网站只用一种字体。** 除非用户明确要求，否则不要搭配两种字体。只有在代码、数据或数字界面中确实需要等宽字体时，才允许在主字体之外使用 Geist Mono。

**禁止使用超粗字重**（900 / black）。最高用到半粗体或粗体。

### 文案规则

**正文中不得使用连字符。** 不要在正文、标题或标签里使用 `-`。改写这句话，不要用连字符。

**不得出现孤字。** 最后一行绝不能只剩一个词。标题使用 `text-wrap: balance`，正文使用 `text-wrap: pretty`。

### 字号阶梯

字号一律对应 Tailwind 的默认字号阶梯。不得保留任意数值，包括 `text-[19px]`、`font-size: 22px` 或 `1.4rem`。

如果已有字号没有正好落在某个阶梯上，就向下取**最接近的那一档**，同时取该档对应的行高。

| 类名 | 字号 | 行高 |
|---|---|---|
| `text-xs` | 12px (0.75rem) | 16px |
| `text-sm` | 14px (0.875rem) | 20px |
| `text-base` | 16px (1rem) | 24px |
| `text-lg` | 18px (1.125rem) | 28px |
| `text-xl` | 20px (1.25rem) | 28px |
| `text-2xl` | 24px (1.5rem) | 32px |
| `text-3xl` | 30px (1.875rem) | 36px |
| `text-4xl` | 36px (2.25rem) | 40px |
| `text-5xl` | 48px (3rem) | 1 |
| `text-6xl` | 60px (3.75rem) | 1 |
| `text-7xl` | 72px (4.5rem) | 1 |
| `text-8xl` | 96px (6rem) | 1 |
| `text-9xl` | 128px (8rem) | 1 |

在评审中，不要把阶梯取整与别处单独设定的自定义行高混用。字距和行高只能在**已匹配阶梯自带的值之内**调整，这样两条规则才不会互相打架。

### 按钮文字

- 主按钮：`text-base`（16px），半粗体。
- 较小的页眉按钮：`text-sm`（14px），半粗体。

## B2. 间距

只用以下数值。不得取中间值，也不得超出这个范围。

| Token | 取值 |
|---|---|
| Spacing-0 | 0 |
| Spacing-25 | 2px |
| Spacing-50 | 4px |
| Spacing-75 | 8px |
| Spacing-100 | 12px |
| Spacing-200 | 16px |
| Spacing-300 | 24px |
| Spacing-400 | 32px |
| Spacing-500 | 40px |
| Spacing-600 | 48px |
| Spacing-700 | 64px |
| Spacing-800 | 80px |
| Spacing-900 | 96px |

**主按钮：** 上下内边距 8px，左右内边距 12px。

## B3. 圆角

只用 Tailwind 的圆角值。

**嵌套圆角公式。** 当一个图形嵌在另一个图形里，且两者之间的间隙**小于 32px** 时：

```
inner radius = outer radius − gap
```

只有当结果**大于 2** 时才用这个公式。小于等于这个值时，内层图形保持直角或不变。

示例：外层卡片为 `rounded-2xl`（16px），内边距为 8px，则内层元素的圆角为 8px（`rounded-lg`）。

## B4. 边框与背景

- **绝不要只给卡片的一边加边框。** 边框要么一圈全加，要么完全不加。
- **背景中禁止使用渐变。** 背景必须是纯色。

### 深色模式背景色

只用以下颜色：

`#000000` · `#181818` · `#1F1F1F` · `#272727` · `#313131` · `#131209`

## B5. 首屏区块

### 标题颜色

- **深色主题：** 标题文字从左到右渐变，`#FFFFFF` → `#9B9B9B`。
- **浅色主题：** 标题文字从左到右渐变，`#000000` → `#666666`。

这是唯一可以使用渐变的地方，而且只用在文字上，绝不要用在背景上。

### 布局

- 标题和副标题的最大宽度均为 **680px**。
- 读一遍标题文案，在**语义完整**的地方换行。
- 换行绝不能把一个短语生硬切断，也不能让句子更难读。要在意思断开的地方换行。

## B6. 图标

**使用：** Phosphor、Solar 或 Iconamoon。

**禁止使用：** Material Icons、Material Symbols。

## B7. 动效

动效应当有分量感，减速落位。绝不要直接使用浏览器默认曲线（`ease`、`linear`、`ease-in-out`）。

**基准曲线：** `ease-[cubic-bezier(0.22,1,0.36,1)]`，布局和位置变化用 `duration-500`。悬停时的颜色和透明度变化可用 `duration-300`，不得短于 200ms。

只对 `transform` 和 `opacity` 做动画。绝不要对 `top`、`left`、`width` 或 `height` 做动画。

尊重 `prefers-reduced-motion`：把移动替换为单纯的透明度变化。

### 导航

**静止状态。** 一个紧凑的导航条，悬浮在顶部边缘之外，而不是紧贴顶部，居中显示，宽度随内容而定。它使用半透明表面加背景模糊，页面内容能在后面隐约可见。间距取自 B2，圆角取自 B3。

**菜单切换。** 打开和关闭图标要在两种状态之间变形，而不是瞬间切换。可以用 B6 中的图标，也可以自己画线条；无论哪种，变化都要用基准曲线做动画。

**移动端菜单。** 以全高面板打开，而不是小的下拉框。面板背景使用主题的基础表面，带高不透明度和强模糊。

**链接入场。** 打开的菜单中的链接按阅读顺序依次出现，每个链接向上移动一小段距离（Spacing-300，24px），同时淡入。每个条目比前一个晚 60ms，整个序列总时长上限为 400ms，这样长菜单也不会感觉拖沓。

### 滚动揭示

进入视口的区块上升一小段距离（Spacing-400，32px），并在基准曲线上用 600 到 800ms 从 0 淡入到完全不透明。每个区块只揭示一次；往回滚动时不要重复播放。

用 `IntersectionObserver` 或 Framer Motion 的 `whileInView` 触发揭示。绝不要把工作挂在未节流的 `window.addEventListener('scroll')` 上，因为它每一帧都会运行，会拖慢移动端性能。

---

## B8. 内容真实感

每一段示例内容都应当读起来像来自一个真实产品、真实用户。

- **写文案。** 不要用占位拉丁文，不要写“你的标题在这里”。要用产品的语气起草真实的句子。
- **人物。** 给证言和团队成员起完整、具体的名字，要符合产品的受众和地区。绝不要让两个人共用同一张脸。
- **品牌与 Logo。** 编造的名字要听起来属于产品所在的行业。物流工具的客户应当听起来像物流公司，而不是通用的科技创业公司。
- **数字。** 避免可疑的整数。定价应当看起来像真实定价，指标应当带小数或以非整数结尾，一组列表中的日期应当各不相同。
- **禁用填充词。** 不要写 "revolutionize"、"supercharge"、"cutting edge"、"effortless"、"transform your workflow"、"take it to the next level"、"harness the power" 或 "world class"。改用平实的语言说明产品到底是做什么的。
- **标题和按钮使用句首大写（sentence case）。**
- **系统消息。** 确认消息要平静、具体（"Invoice sent to Dana"）。错误消息要说明失败了什么、下一步该做什么（"Upload failed. The file is over 20 MB."）。不要用俏皮的感叹词，不要用感叹号。

## B9. 状态

每个可交互元素都要带齐完整的状态组合：

- **悬停（Hover）** —— 背景变化、轻微缩放或位移
- **激活（Active）** —— `scale(0.98)` 或 `translateY(1px)`，提供真实的按压反馈
- **聚焦（Focus）** —— 可见的聚焦环。这是无障碍要求，不是可选项。
- **加载（Loading）** —— 与真实布局形状一致的骨架屏，而不是圆形旋转器
- **空状态（Empty）** —— 排版完整的“开始使用”视图，绝不是空白面板
- **错误（Error）** —— 行内、具体。绝不要用 `window.alert()`。

不得有死链接。指向 `#` 的按钮要么补上真实链接，要么在视觉上置灰禁用。当前页面必须在导航中标示出来。

## B10. 上线要求

这些是容易被遗忘、会让页面显得未完成的地方：

- 页脚中的隐私政策和服务条款链接
- 自定义的、带品牌感的 404 页面
- 客户端表单校验：邮箱格式和必填项
- 面向键盘用户的“跳转到正文”链接
- 在司法管辖区要求时提供 Cookie 同意
- 带品牌感的 favicon
- `<title>`、meta 描述、`og:image` 和社交分享标签
- 每个有意义的图片都要有 Alt 文本
- 语义化 HTML：`<nav>`、`<main>`、`<article>`、`<aside>`、`<section>`
- 每个页面都要有返回路径

## B11. 标语揭示区块（强制）

每个落地页都要包含一个用大字呈现核心收益或标语的区块，独立于首屏。它位于页面更下方，作为自己的一个高光时刻，不要直接堆在首屏下面。

**文案**
- 至少两行文字。
- 是收益陈述或标语，按 A5 的语气写，而不是通用的区块标题。

**字体排版**
- 字号按行数取 `text-4xl` 到 `text-6xl`，遵循 B1 的字号阶梯。
- 最大宽度与首屏一致，按 B5 的规则在语义完整的地方换行。

**动效**
- 文字初始为柔和的弱化色调，约为主题基础文字颜色的 25% 到 35% 不透明度。
- 当区块滚动进入视口时，每个词按阅读顺序逐个从弱化色调过渡到完整文字颜色。
- 词是逐个越过触发线激活的，不是整块一次性翻转。过渡使用 B7 的基准曲线，绝不要用线性淡入。
- 用每个词一个 `IntersectionObserver` 实现，或用一个经 `requestAnimationFrame` 节流的滚动监听器实现。按 B7 的要求，绝不要用未节流的 `window.addEventListener('scroll')`。

# 输出格式

从零生成落地页时，在写代码之前，先按以下顺序返回：

1. **页面大纲** —— 区块及其顺序
2. **首屏文案** —— 标题、副标题、CTA、证明行
3. **收益** —— 三到五条以结果为导向的要点
4. **使用方法** —— 三个步骤
5. **FAQ** —— 六到十二个问题及答案
6. **SEO / AEO** —— 收录或不收录的建议，如果收录，还要给出标题和 meta
7. **版式建议** —— A、B、C 或 D，以及为什么选它

然后按 A6 的顺序，一个区块一个区块地搭建。

# 快速检查清单

**策略**
- [ ] 一个卖点、一个受众、一个核心行动
- [ ] 首屏上方没有相互竞争的 CTA
- [ ] 用具体数字，而不是含糊的动词
- [ ] 至少一种风险逆转
- [ ] 证明放在它所支撑的主张旁边
- [ ] 版式类型是经过深思熟虑选择的

**视觉**
- [ ] 只用一种获批字体，无斜体，无超粗字重
- [ ] 文案中无连字符，无孤字
- [ ] 每个字号都落在 Tailwind 阶梯上
- [ ] 每个间距值都来自间距表
- [ ] 嵌套圆角遵循公式
- [ ] 没有单边卡片边框，背景没有渐变
- [ ] 首屏标题和副标题上限为 680px，并在语义完整处换行
- [ ] 图标来自 Phosphor、Solar 或 Iconamoon
- [ ] 每个过渡都用 B7 基准曲线，滚动揭示用 IntersectionObserver
- [ ] 标语揭示区块已存在，至少两行，滚动时词逐个激活

**内容与上线**
- [ ] 真实的起草文案、可信的人名和数字、无禁用填充词
- [ ] 悬停、激活、聚焦、加载、空状态、错误状态齐全
- [ ] 无死链接，当前导航项已标示
- [ ] 404、法律链接、表单校验、favicon、meta 标签、Alt 文本齐全
